# Mobile permissions audit

This audit records the launch permission posture for the Agent Tick mobile app. It is intended for app-store review, privacy answers, and regression checks before building native binaries.

## Scope

Reviewed surfaces:

- Expo app configuration: `apps/mobile/app.json`
- Mobile QR scanner usage in `apps/mobile/App.tsx`
- Installed Expo camera config plugin behavior
- Store-facing privacy concern from Fizzy #26 / #27: Android `RECORD_AUDIO`

## Current declared permissions

| Platform | Permission / capability | Status | Why it is needed | Store-review note |
| --- | --- | --- | --- | --- |
| Android | `android.permission.CAMERA` | Declared | QR pairing scans an Agent Tick pairing code from the CLI/web setup flow. | Explain as QR-code scanning only. Agent Tick does not use the camera for surveillance, content capture, face recognition, or background collection. |
| Android | `android.permission.RECORD_AUDIO` | Removed / disabled | Not needed for launch. The app does not record audio or video for approval workflows. | No Play Console microphone justification should be required for the current build. |
| iOS | `NSCameraUsageDescription` | Generated by `expo-camera` with custom copy | QR pairing scans an Agent Tick pairing code. | Use the configured copy: “Allow Agent Tick to scan pairing QR codes.” |
| iOS | `NSMicrophoneUsageDescription` | Disabled | Not needed for launch. | Should not appear in the generated native config for the current build. |
| iOS / Android | Push notification capability | Expected via `expo-notifications` | Approval alerts and setup/test notifications. | Explain that notifications are used to alert the signed-in human when an approval needs attention. |
| iOS / Android | Secure storage/keychain/keystore access | Expected via `expo-secure-store` | Local account, pairing, and token state. | Explain as on-device secure storage for authentication/connection state. Do not claim it stores raw approval content unless implementation changes. |

## Expo camera guardrails

`expo-camera` can add microphone-related native configuration by default. Agent Tick uses the camera only as a QR scanner, so `apps/mobile/app.json` configures the plugin explicitly:

```json
[
  "expo-camera",
  {
    "cameraPermission": "Allow Agent Tick to scan pairing QR codes.",
    "microphonePermission": false,
    "recordAudioAndroid": false
  }
]
```

Keep these settings unless Agent Tick later adds an intentionally reviewed audio/video recording feature.

## Reviewer explanation

If app review asks why camera access is present:

> Agent Tick uses camera access only to scan a QR pairing code during setup. The pairing code connects the signed-in mobile app to the user's Agent Tick CLI or server. The app does not record audio, record video, perform face recognition, or collect camera content in the background.

If Play Console still reports microphone access after a native rebuild, check generated native manifests/config first. `RECORD_AUDIO` should not be present when `recordAudioAndroid` is `false`.

## Regression checks

Run these before store submission builds:

```bash
node -e "const fs=require('fs'); const c=JSON.parse(fs.readFileSync('apps/mobile/app.json','utf8')); const cam=c.expo.plugins.find(p=>Array.isArray(p)&&p[0]==='expo-camera'); if (c.expo.android.permissions.includes('android.permission.RECORD_AUDIO')) throw new Error('RECORD_AUDIO still declared'); if (cam[1].recordAudioAndroid !== false) throw new Error('recordAudioAndroid is not false'); if (cam[1].microphonePermission !== false) throw new Error('microphonePermission is not false'); console.log('permission config ok');"
corepack pnpm --filter @agent-tick/mobile exec expo config --type public --json > /tmp/agenttick-mobile-expo-config.json
python3 - <<'PY'
import json
c=json.load(open('/tmp/agenttick-mobile-expo-config.json'))
perms=c['android'].get('permissions', [])
assert 'android.permission.RECORD_AUDIO' not in perms, perms
assert 'android.permission.CAMERA' in perms, perms
print('expo public config ok:', perms)
PY
```
