Agent Tick CLI UX assessment

Current vs recommended command experience

This report compares the current CLI behavior with a recommended UX direction focused on making the everyday Agent Tick commands obvious, example-driven, colorful, and forgiving.

Current state

  • Top-level help is generated by Commander and lists commands alphabetically / structurally, not by user importance.
  • The three product primitives — status, steering, and sanction — are buried in the command list.
  • Help lacks concrete copy-paste examples.
  • Errors are terse and force users to re-run --help.
  • setup --login, the main hosted-product sign-in path, is not prominent.
  • hook, an internal integration command, appears in normal help.
  • steering --choice requires advanced syntax and rejects natural inputs like --choice "nothing".

Recommended state

  • Top-level help should start with the three everyday commands and examples.
  • Use color when attached to a TTY, while respecting NO_COLOR.
  • Every validation error should immediately print a short command-specific help block and example.
  • Make browser sign-in prominent via agent-tick setup --login and preferably a friendly alias such as agent-tick login.
  • Hide internal hook commands from normal help.
  • Allow label-only steering choices and auto-add a cancel / deny choice when needed.

Command-by-command assessment

CommandCurrent UXRecommended UX
status Requires a message, but agent-tick status only says status requires a message. Print examples immediately: agent-tick status "Finished edits; running tests" and agent-tick status --state blocked "Need staging access".
steering Requires --title and strict --choice id=Label syntax. Natural choices are rejected. Show a full example on error. Accept label-only choices like --choice "nothing". Auto-add a cancel/deny choice if none is supplied.
sanction Reasonable default title, but help should better distinguish action approval from command approval. Show both examples prominently: agent-tick sanction --title "Proceed?" and agent-tick sanction -- npm install.
setup setup --login exists but is not presented as the main path. Running setup errors. Make browser login the first example. Consider adding agent-tick login as a friendly alias. Keep setup --token as manual/self-hosted.
install Useful, but help does not orient Claude Code users quickly. Prominent example: agent-tick install --target claude. Include local/global scope and sandbox examples in detailed help.
mode Good small command, but needs context in help. Explain afk vs pass-through and tie it directly to Claude Code routing.
abandon Fine as an advanced command. Keep lower in help. Include example with a request id.
hook Visible in normal top-level help despite being internal. Hide from normal help. Still available for installed Claude hooks.

Error UX: current

$ agent-tick steering
error: required option '--title <title>' not specified

$ agent-tick steering --title "test"
steering requires at least one --choice

$ agent-tick steering --title "test" --choice "nothing"
invalid choice: nothing. Use id=Label or id:kind=Label.

Error UX: recommended

Missing required option: --title

Ask a human to steer the work:
  agent-tick steering --title "Which approach?" \
    --choice "Small targeted fix" \
    --choice "Refactor now" \
    --choice stop:deny="Stop"

Run `agent-tick steering --help` for all options.

Color recommendation

  • Green: successful setup, sent status, approved sanction.
  • Yellow: missing required input, timeout, dry-run warnings.
  • Red: failed request, denied sanction, invalid config.
  • Cyan/blue: section headings and command names.
  • Dim gray: advanced notes, environment variables, internal details.

Only emit color when stdout/stderr is a TTY. Respect NO_COLOR and consider FORCE_COLOR.

Implementation recommendations

  1. Replace default top-level Commander help with a custom, example-first help renderer.
  2. Add custom help text and examples for each public command.
  3. Install a centralized error handler that catches validation errors and prints command-specific guidance.
  4. Make steering --choice accept label-only values and automatically include a deny/cancel choice when absent.
  5. Add agent-tick login as an alias for agent-tick setup --login.
  6. Hide hook from normal help.
  7. Keep self-hosted token setup visible but clearly secondary: agent-tick setup --server ... --token ....

Everyday:
