# Session Stack for the Native App approval flow

The Native App replaces global latest-status banners and request/source selector strips with full Session views and a Session Stack. A Session Stack shows multiple unarchived Session Lanes as clipped mini-window viewports into each Session's full timeline content; tapping a lane in Stack Mode expands that viewport into full Session detail, where Requests are answered and Status Updates, Requests, and responses appear in chronological context.

This deliberately rejects separate summary-card previews. Session Lanes keep only minimal stack chrome for stable Session title, Session State, and lane size controls; the inner viewport uses the same full-detail timeline components at normal size and normal width rules, with hard clipping. Lanes anchor on the newest actionable Request when input is needed, otherwise on latest activity with preceding activity filling available height. The stack uses useful minimum lane heights and scrolls when the lanes do not fit, instead of shrinking lanes into unusable slivers. Collapsed lanes show title-bar height only; a single large lane may claim about half the stack when possible.

Session Lane order is manual local state, not a priority sort. New Sessions append to the existing manual order, and long-pressing a lane title bar temporarily collapses lanes while the user drags/releases the lane into position. There is no user-facing Session Stack sorting preference. Lane size is local state: pressing the size control toggles collapsed versus the current effective size; long-pressing toggles the non-collapsed size between normal and large.

The Stack has two interaction modes. Stack Mode treats lanes as non-interactive previews and navigation targets; visible controls inside a lane never submit and open full detail instead. Overview Mode treats lanes as independently scrollable, interactive Session windows, so users can operate directly inside multiple Session timelines without entering full detail.

The trade-off is implementation complexity and the need to load timeline details for visible lanes in exchange for spatial continuity: the Stack is a set of mini Sessions, not a request list. The full detail and lane viewport should share the same timeline renderer so the two surfaces cannot drift into separate designs. Opening and returning use the same shared-view relationship, expanding or collapsing the viewport without scaling the timeline content, so the user experiences the selected Session as the same object moving between stack and full-detail states. Reduced-motion or constrained platforms preserve the same target position with instant or near-instant navigation rather than decorative motion.

Attention indicators are request-action oriented rather than generic unread counters. The Stack actions button remains a neutral `⋯` control and may show the visible lane count as low-emphasis background text, not an urgency badge. If actionable pending Requests are in offscreen lanes, the Stack shows directional offscreen pending indicators such as `↑ 1` or `↓ 2`; tapping one scrolls toward the nearest offscreen pending Session Lane. Generic unread counts/dots are avoided because pending/responded Request state is the meaningful server-authoritative attention signal.
