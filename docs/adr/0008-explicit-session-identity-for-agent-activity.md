# Explicit Session identity for Agent Activity

Agent Tick groups Requests and Status Updates into Sessions that represent one host agent chat, thread, or run. Explicit `sessionId` remains the canonical grouping boundary when it is supplied by the caller or by a host integration that knows the real chat/thread/session ID. Work-area hints such as host, working directory, client name, and Agent Connection label are source metadata, not Session identity. Activity without explicit Session identity is grouped best-effort by stable source metadata such as agent/client name, host, and working directory. Session is derived from grouped Agent Activity first, not a separately managed server lifecycle entity, and the server exposes derived Session summaries plus separate full timeline detail for clients. Derived Session titles prefer host/integration-provided labels and fall back to latest meaningful Activity, while local device presentation overrides such as title or color remain client-side customizations for one Session by default. Existing Status Update `threadId` input is legacy/source metadata; **Session** is the user-facing concept and the shared grouping boundary for Native App, Personal Console Activity, and history/archive views. See [ADR 0011](./0011-host-chat-session-identity-resolution.md) for host-specific Session ID resolution.
