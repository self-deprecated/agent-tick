## Goal

Rewrite the `agent-tick` CLI using Charmbracelet Fang (cobra + lipgloss) so every subcommand has a rich, styled, example-laden help screen. As part of the same rewrite, expose every environment variable the CLI reads as a command-line flag (flag > env var > default precedence).

## Acceptance Criteria

### CLI framework & help

- [ ] `apps/server/cmd/agent-tick/main.go` is migrated from stdlib `flag` to `github.com/spf13/cobra` wrapped by `github.com/charmbracelet/fang`.
- [ ] All existing subcommands preserve identical flag names and behaviour: `setup`, `server`, `request`, `guard`, `pair`, `agent-token` (with `list`, `revoke`, `rotate` subcommands), `adapter`.
- [ ] Top-level `agent-tick --help` shows a styled summary, grouped subcommands, and one global usage example.
- [ ] Each subcommand's `--help` includes:
  - Short description
  - Long description (1–3 sentences of context)
  - Full flag list (auto-generated by cobra)
  - **Multiple usage examples** (at minimum: one common case + one advanced case per subcommand)
  - A **See also** section cross-referencing related subcommands (e.g. `pair` → `agent-token`; `setup` → `server`; `request` → `guard`).
- [ ] Fang's default theme is used (no custom palette).
- [ ] `NO_COLOR` is respected (Fang handles this automatically via lipgloss; verify during testing).

### Env vars as flags

- [ ] Every env var the CLI currently reads is also settable via a flag on the relevant subcommand, with precedence **flag > env var > default**:
  - `AGENT_TICK_SERVER` → `--server` (already exists; keep)
  - `AGENT_TICK_TOKEN` → `--token` (on `server` for admin auth; also used as the default for client commands)
  - `AGENT_TICK_MODE` → `--mode` (on `server`)
  - `AGENT_TICK_PUBLIC_URL` → `--public-url` (on `server`)
  - `AGENT_TICK_REQUIRE_SIGNATURE` → `--require-signature` (bool flag on `server`)
  - `AGENT_TICK_CONFIG` → `--config` (global)
  - `AGENT_TICK_REQUESTER` → `--requester` (on `request`, `guard`, `adapter`)
  - `AGENT_TICK_AGENT_ID` → `--agent-id` (on `request`, `guard`, `adapter`)
- [ ] Every flag's help string ends with `[env: AGENT_TICK_FOO]` inline, naming its backing env var.
- [ ] Unit tests cover precedence for at least one representative flag: set env var + pass flag → flag wins; unset flag → env wins; unset both → default.

### General

- [ ] Existing tests in `main_test.go` still pass (update call sites if the public surface changes, but keep the same CLI args).
- [ ] `go build ./...` and `go test ./...` pass.

## Design Decisions

- **CLI framework**: Charmbracelet Fang wrapping Cobra. Chosen because Fang ships lipgloss-styled help out of the box, avoiding hand-rolled styling code.
- **Help depth**: Rich — description, flags, multiple examples, and a "See also" cross-reference section on each subcommand.
- **Colour scheme**: Fang default theme. Do not customise the palette.
- **Env/flag precedence**: flag > environment variable > default. Standard Unix convention.
- **Env var documentation**: flag help strings include `[env: AGENT_TICK_FOO]` for discoverability.
- **Merged scope**: env-var-as-flag work is combined with the Fang migration because both rewrite CLI flag handling; splitting them would throw away the initial cobra flag wiring when env binding is added.

## Implementation Notes

- Add dependencies: `github.com/charmbracelet/fang` and `github.com/spf13/cobra`. Run `go mod tidy`.
- Structure: one `cobra.Command` per subcommand, grouped into a root command; wrap the root with `fang.Execute(ctx, rootCmd)` in `main()`.
- For env binding: a small helper that calls `os.Getenv` to set the flag default is enough — do NOT pull in viper just for this.
- Preserve flag names and env var names exactly — this is a user-facing interface. Existing integrations (scripts, docs, deployments) must keep working.
- `agent-token` currently uses manual sub-subcommand dispatch (list/revoke/rotate); migrate these to nested `cobra.Command` children.
- For boolean env vars (`AGENT_TICK_REQUIRE_SIGNATURE`), accept `1`, `true`, `yes` as truthy; everything else is false. At minimum match the current `== "1"` behaviour.
- Global flags (`--config`) should be attached to the root command, not individual subcommands.
- Examples should be realistic (real-looking URLs, tokens as `<placeholder>` — never real secrets).
- "See also" links: plain text in help (cobra has no native cross-reference support).
